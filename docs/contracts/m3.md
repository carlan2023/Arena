## 3. Engine: packages/ludo_tutorial (new, owner Engine)

Pure Dart, depends on ludo_engine and ludo_bots.

```dart
class TutorialLesson {
  final String id;            // release, combine, block, break_block, exact_finish
  final String titleKey;      // l10n keys, the app looks up the text
  final String introKey;
  final GameState start;      // a hand built position
  final List<(int, int)> dice;          // the rolls for this lesson, in order
  final List<TutorialStep> steps;       // what the player must do and what the bot does
}
class TutorialStep {
  final String hintKey;
  final bool Function(GameState before, List<Move> played) accepts; // the player's move list for the roll
  final List<Move>? botMoves;           // scripted opponent reply, or null for the player's roll
}
List<TutorialLesson> tutorialLessons();       // the five lessons, in order
```

Each lesson is tested by playing its script through the engine to its goal.

Teams (M3.8): check every teams rule (R7, R8 both ways, partner capture, finished player rolling for partner, forfeit) is covered by named tests, and that NormalBot avoids capturing a partner unless forced and protects the partner's pieces. Bot levels: the server uses BotLevel.normal for seat filling and timeouts; easy stays for practice.

## 4. Protocol additions (owner Server)

New HTTP routes. All need a bearer token. Guests may use profile, coins, quick match for free and coin tables, and the tutorial reward. Everything touching UGX needs a phone login (403 phone_required), a date of birth (403 age_required) and no active self exclusion (403 self_excluded).

| Method and path | Body | Response |
|---|---|---|
| GET /v1/me | | User now also has `avatar: int`, `coins: int`, `dateOfBirth: str?` (yyyy-mm-dd, only to its owner) |
| PATCH /v1/me | `{"displayName"?, "avatar"?}` | User |
| POST /v1/me/date-of-birth | `{"dateOfBirth": "1995-04-01"}` | User. Once only; 409 if already set. 403 age_required if under MIN_AGE (still stored) |
| GET /v1/coins | | `{"balance", "dailyReward": {"available": bool, "amount": int, "streak": int, "nextAt": iso8601}}` |
| POST /v1/coins/daily | | `{"balance", "granted": int, "streak": int}`; 409 already_claimed |
| POST /v1/tutorial/complete | | `{"balance", "granted": int}`; granted 0 if already rewarded |
| GET /v1/tables | | `{"coin": [entries], "paid": [stakes], "paidEnabled": bool}` |
| GET /v1/wallet/limits | | `{"daily", "weekly", "monthly", "pending": {...}?, "excludedUntil": iso8601?, "permanent": bool}` |
| PUT /v1/wallet/limits | `{"daily"?, "weekly"?, "monthly"?}` | the limits |
| POST /v1/wallet/self-exclusion | `{"period": "1d"\|"7d"\|"30d"\|"6m"\|"permanent"}` | the limits |
| POST /v1/wallet/withdrawals | `{"amount", "msisdn", "provider"}` | Withdrawal |
| GET /v1/wallet/withdrawals/{id} | | Withdrawal |
| POST /v1/admin/withdrawals/{id}/approve and /reject | | Withdrawal. Needs ADMIN_TOKEN as the bearer, not a user token |
| GET /v1/matches/recent | | `{"matches": [{"matchId", "mode", "stake", "entry", "endedAt", "rank", "players": [...] }]}` last 20 |

Room creation gains `entry: int` (coins, default 0). `stake` above 0 creates a paid 1v1 room when PAID_TABLES_ENABLED, else 403 paid_tables_disabled.

New web socket messages:

| Direction | type | Fields |
|---|---|---|
| App to server | queue_join | `mode: "oneVsOne"\|"freeForAll", entry: int, stake: int` |
| App to server | queue_leave | |
| Server to app | queue_status | `seq?, state: "waiting"\|"matched"\|"timeout"\|"cancelled", waited: int (seconds), playersFound: int, botFillAt: int? (epoch ms), roomCode: str?` |
| Server to app | wallet_update | `balance: int, coins: int, reason: str` after any stake, payout, refund or coin change |

When matched, the app receives queue_status matched with a roomCode and joins it with join_room as usual. A socket in a queue is not bound to a room until it joins.

Room additions: Room gains `entry: int`, and PlayerView gains `avatar: int`. game_over gains `coinsDelta: {userId: int}` next to walletDelta.

New error codes: `age_required`, `self_excluded`, `limit_exceeded`, `already_claimed`, `queue_busy` (already in a queue or room), `not_found`.

Stake and entry flow, enforced on the server:
1. A paid or coin seat is charged when the game starts, not on join: the server asks the wallet to move each player's stake or entry into the match pot. If any charge fails (insufficient_funds, self_excluded), nobody is charged, that player is removed from the room with an error, and the room goes back to waiting.
2. At game over the server asks the wallet to settle the pot by the ranking.
3. A game abandoned before any move refunds every stake. A forfeit counts as a loss.

CORS: the server answers browser preflight and adds Access-Control-Allow-Origin for origins listed in ALLOWED_ORIGINS (default https://arena-cddfa.web.app,https://arena-cddfa.firebaseapp.com,http://localhost:*). The web socket checks the same list.

## 5. Wallet additions (owner Wallet)

All new stores have in memory and Postgres versions; all money is integers; every movement is ledger transfers with an idempotency key.

```dart

// UserStore gains: setAvatar(id, avatar), setDateOfBirth(id, date) (once).

// Coins (arena_wallet)
class CoinService {
  CoinService({required Ledger ledger, required CoinSettings settings, DateTime Function()? clock});
  Future<int> grantSignup(String userId);                 // key coins:signup:<userId>, once
  Future<DailyRewardStatus> dailyStatus(String userId);
  Future<DailyRewardGrant> claimDaily(String userId);      // key coins:daily:<userId>:<yyyy-mm-dd Kampala>; throws AlreadyClaimedException
  Future<int> grantTutorial(String userId);                // key coins:tutorial:<userId>, returns 0 if already granted
  Future<int> balance(String userId);
}

// Tables and settlement (arena_wallet)
class MatchStakes { final String matchId; final Currency currency; final int perPlayer; final List<String> userIds; }
class SettlementService {
  SettlementService({required Ledger ledger, required PayoutSettings payout, required CoinTableSettings coins});

  /// ranking is userIds in finishing order, forfeits last. Key settle:<matchId>. Pays per README section 10 for UGX
  /// (winner, house share to revenue, rake tax to taxPayable, withholding to taxWithheld) and per D37 for coins.
  Future<Map<String, int>> settle(String matchId, List<String> ranking);   // returns each user's net change

  /// Throws SelfExcludedException or LimitExceededException. Called by deposits and by collectStakes for UGX.
  Future<void> checkDeposit(String userId, int amount);
  Future<void> checkPlay(String userId);
}
bool isOldEnough(DateTime dateOfBirth, DateTime now, int minAge);

// Withdrawals (arena_wallet)
abstract interface class PayoutProvider {                   // disbursements; fake, MTN Disbursements, Airtel Disbursements
  String get name;
  Future<ProviderAck> requestPayout(PayoutRequest request);
  Future<ProviderStatus> checkStatus(String providerRef);
  CallbackEvent? parseCallback(Map<String, String> headers, String body);
}
class WithdrawalService {
  // request: checks phone, age, amount range, balance; moves amount wallet -> withdrawalPending (key withdraw:<id>);
  //   below MANUAL_REVIEW_UGX sends to the provider at once, else waits for approve().
  // approve / reject (admin); handleCallback / refresh like deposits;
  // success: withdrawalPending -> providerClearing; failure or reject: withdrawalPending -> wallet. Each transfer keyed, safe to repeat.
}
// AccountKind gains withdrawalPending.

// Provider switch (M3.12): one factory builds providers from settings; PAYMENTS_PROVIDER and PAYOUTS_PROVIDER
// accept fake, mtn, airtel or a comma list; real providers need LIVE_PAYMENTS=true as well, so a stray setting

// Reconciliation (M4.6)
abstract interface class StatementSource { Future<List<StatementLine>> lines(String provider, DateTime day); }
class ReconciliationService {
  /// Compares a day's settled payments and withdrawals with the provider statement and the ledger.

  Future<ReconciliationReport> reconcile(String provider, DateTime day);
```

### Product defaults added (placeholders for Allan)

1. D45 Teams stay free only in M3: creating or queueing a teams game with entry or stake above 0 is bad_request.
2. D46 Paid play only through quick match. A private room with stake above 0 is refused with paid_tables_disabled, so friends cannot pass money to each other (README section 10).
3. D47 Coin tables with bots: the house account `revenue:house:coin` pays each bot's entry; if a bot wins, the pot goes back to the house. 3 player coin game: the winner takes the pot. 4 player: winner takes the pot less the 2nd place refund (D37).
4. D48 The 500 coin welcome grant is paid on the account's first finished online game, not at sign up, so guest accounts cannot farm coins.
5. D49 Guest to phone: logging in with a phone while holding a guest token turns the guest into the phone account (same id, coins, avatar, history) when the phone has no account yet. If the phone already has an account, that account is used and the guest's coins stay with the old guest; the app warns before this.
6. D50 Paid matches: a paid game that ends with no connected human (both dropped, or a server restart) is refunded. "Before any move" means before the first roll. Coin games behave like free games on timeouts (bot takeover), paid games forfeit.
7. D51 Withdrawals go only to the account's own verified phone number. Daily withdrawal cap 2,000,000 UGX. Provider fees are paid by the house and not recorded in M3.
8. D52 Limits are rolling 24 hour, 7 day and 30 day windows over deposits started (pending and succeeded). Limits apply to deposits only. No personal limit means only the house cap. Lowering cancels a pending raise. Self exclusion can only be extended from the app.
9. D53 Date of birth: the app shows it spelled out and asks for confirmation before sending. Support can correct it through an admin route.
10. D54 Avatars are drawn in code from shape and colour sets, no image files.
11. D55 Flavours: the full flavour has application id suffix `.full` and its own name "Arena Full" (placeholder) so it installs next to the Play app. The play flavour contains no paid code and no link to the full download. The flavour always wins in the app, whatever the server says. The web app is the play flavour. Builds without FLAVOR are play.
12. D56 Languages: an in app setting (English or Luganda), defaulting to the phone language, else English.
13. D57 The tutorial reward is trusted from the app (known limit: worth 50 coins once per account).

### Engine and tutorial

14. Each `TutorialStep` carries its own `(int, int) roll` (player and scripted bot rolls, in play order); `TutorialLesson.dice` is dropped. Each player step has one expected end state; `accepts` is true for any legal sequence reaching it. Steps carry `List<Move> suggested` for the app to highlight, and `TutorialStep.check(before, played)` returns ok or wrong with a hintKey. Lessons are oneVsOne, red player against a scripted yellow, default rules; ludo_tutorial depends only on ludo_engine. Every text key is listed in a const list with a uniqueness test; the app has a test that each exists in app_en.arb.
15. In teams `ranking()` lists the winning team first (both partners in finish order), then the others. NormalBot: never captures a partner unless forced, values capturing a threat to a partner piece, scores partner pieces as its own when rolling for the partner, values joint blocks like its own under R8 joint; one named test per point. Its danger check also counts opponents at home who can release onto their start square. A named test for the forced partner capture. bots_api: `chooseMoves` is synchronous and pure.

### Server and protocol

16. Queue: a waiting entry leaves the queue at once when its socket closes. A player matched while offline keeps the seat under the normal reconnect grace, and queue_join after reconnecting returns queue_status matched with the roomCode instead of queue_busy. queue_status and wallet_update carry no seq; queue_status carries `serverNow`. wallet_update goes to every open socket of the user; the app also refreshes from HTTP.
17. Paid queue joins check phone, age, self exclusion and balance up front and fail fast; collectStakes checks again. A failed charge in a queue made room cancels it: the player who could pay goes back to the front of the queue (queue_status waiting), the other gets queue_status cancelled and the error.
18. Game start becomes a charging step: the room stays waiting, joins and leaves get already_started while it runs. A new matchId for every game. matches gain `settled_at`; on start the server retries settle or refund for ended matches not yet settled. A sweep refreshes deposits and withdrawals pending more than 10 minutes.
19. Room creation: at most one of entry and stake above 0, entry one of D37, stake one of D38, else bad_request. Room and room_state gain `turnSeconds`.
20. GET /v1/matches/recent players: `[{seat, userId, displayName, avatar, color, isBot, place}]`; the caller's place is `rank`; entry and stake 0 when unused.
21. Withdrawal: `{id, amount, msisdn, provider, status: "review"|"pending"|"succeeded"|"failed"|"rejected", createdAt}`. Limits pending: `{daily?, weekly?, monthly?, effectiveAt}`; a null limit means only the house cap. Wallet history kinds: deposit, withdrawal, withdrawal_refund, stake, payout, refund, coin_grant, coin_entry, coin_payout.
22. New routes: `POST/PUT /v1/payouts/callback/{provider}`, `POST /v1/admin/users/{id}/date-of-birth`. Admin routes need ADMIN_TOKEN (at least 32 bytes, compared in constant time) and return 404 when it is unset. Server owns every route; the wallet packages provide the services.
23. Error statuses: queue_busy 409, already_claimed 409, limit_exceeded 403, age_required 403, self_excluded 403, not_found 404. A Firebase key fetch failure maps to 503, not 401.
24. `ArenaClient.next` defaults to messages after the call; pass `after: 0` to search history.

### Wallet

25. Additive: `Ledger.txIdForKey(key)`, `PaymentStore.sumStartedSince(userId, since)`, `UserStore.attachPhone(guestId, identity)`, `UserStore.setAvatar`, `setDateOfBirth`, `correctDateOfBirth` (admin), new CoinStore and LimitsStore (memory and Postgres).
26. Daily reward: after day 7 it stays at 220; nextAt is the next Kampala midnight; coins come from `revenue:house:coin`; the ledger key is the double grant guard (post first, duplicate means already claimed).
27. SettlementService takes a LimitsService and `settle(matchId, ranking, winners)`; it handles UGX and coins, and bot seats funded by the house (D47). Phone and age checks stay in the server. Settle after refund or refund after settle throws StateError.
28. Withdrawals: refund the pending amount only on a definite failure (provider failed, or a 4xx); timeouts stay pending for review. withdrawalPending accounts use ref = userId. MTN Disbursements and Airtel disbursement credentials are new settings (Server config).
29. Provider switch: sandbox endpoints need no LIVE_PAYMENTS; only production endpoints or environments need LIVE_PAYMENTS=true. `buildProviders(ProviderSettings)` takes plain values from the server config. D30 (everything goes to fake) applies only when the provider list is exactly `fake`.
30. Reconciliation reads provider CSV exports through one CsvStatementSource. StatementLine: providerRef, externalId, type (deposit or payout), amount, status, time; days are Kampala days. The report also lists payments pending over 24 hours and providerClearing against the statement total.
