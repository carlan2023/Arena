## 4. Protocol additions (owner Server)

New HTTP routes. All need a bearer token. Guests may use profile, coins, quick match for free and coin tables, and the tutorial reward. Everything touching UGX needs a phone login (403 phone_required), a date of birth (403 age_required) and no active self exclusion (403 self_excluded).

| Method and path | Body | Response |
|---|---|---|
| GET /v1/me | | User now also has `avatar: int`, `coins: int`, `dateOfBirth: str?` (yyyy-mm-dd, only to its owner) |
| PATCH /v1/me | `{"displayName"?, "avatar"?}` | User |
| POST /v1/me/date-of-birth | `{"dateOfBirth": "1995-04-01"}` | User. Once only; 409 if already set. 403 age_required if under MIN_AGE (still stored) |
| GET /v1/coins | | `{"balance", "dailyReward": {"available": bool, "amount": int, "streak": int, "nextAt": iso8601}}` |
| POST /v1/coins/daily | | `{"balance", "granted": int, "streak": int}`; 409 already_claimed |
| POST /v1/tutorial/complete | | `{"balance", "granted": int}`; granted 0 if already rewarded |
| GET /v1/tables | | `{"coin": [entries], "paid": [stakes], "paidEnabled": bool}` |
| GET /v1/wallet/limits | | `{"daily", "weekly", "monthly", "pending": {...}?, "excludedUntil": iso8601?, "permanent": bool}` |
| PUT /v1/wallet/limits | `{"daily"?, "weekly"?, "monthly"?}` | the limits |
| POST /v1/wallet/self-exclusion | `{"period": "1d"\|"7d"\|"30d"\|"6m"\|"permanent"}` | the limits |
| POST /v1/wallet/withdrawals | `{"amount", "msisdn", "provider"}` | Withdrawal |
| GET /v1/wallet/withdrawals/{id} | | Withdrawal |
| POST /v1/admin/withdrawals/{id}/approve and /reject | | Withdrawal. Needs ADMIN_TOKEN as the bearer, not a user token |
| GET /v1/matches/recent | | `{"matches": [{"matchId", "mode", "stake", "entry", "endedAt", "rank", "players": [...] }]}` last 20 |

Room creation gains `entry: int` (coins, default 0). `stake` above 0 creates a paid 1v1 room when PAID_TABLES_ENABLED, else 403 paid_tables_disabled.

New web socket messages:

| Direction | type | Fields |
|---|---|---|
| App to server | queue_join | `mode: "oneVsOne"\|"freeForAll", entry: int, stake: int` |
| App to server | queue_leave | |
| Server to app | queue_status | `seq?, state: "waiting"\|"matched"\|"timeout"\|"cancelled", waited: int (seconds), playersFound: int, botFillAt: int? (epoch ms), roomCode: str?` |
| Server to app | wallet_update | `balance: int, coins: int, reason: str` after any stake, payout, refund or coin change |

When matched, the app receives queue_status matched with a roomCode and joins it with join_room as usual. A socket in a queue is not bound to a room until it joins.

Room additions: Room gains `entry: int`, and PlayerView gains `avatar: int`. game_over gains `coinsDelta: {userId: int}` next to walletDelta.

New error codes: `age_required`, `self_excluded`, `limit_exceeded`, `already_claimed`, `queue_busy` (already in a queue or room), `not_found`.

Stake and entry flow, enforced on the server:
1. A paid or coin seat is charged when the game starts, not on join: the server asks the wallet to move each player's stake or entry into the match pot. If any charge fails (insufficient_funds, self_excluded), nobody is charged, that player is removed from the room with an error, and the room goes back to waiting.
2. At game over the server asks the wallet to settle the pot by the ranking.
3. A game abandoned before any move refunds every stake. A forfeit counts as a loss.

CORS: the server answers browser preflight and adds Access-Control-Allow-Origin for origins listed in ALLOWED_ORIGINS (default https://arena-cddfa.web.app,https://arena-cddfa.firebaseapp.com,http://localhost:*). The web socket checks the same list.

## 7. Amendments

Overrides anything above that disagrees.

### M3.1 quick match (13 Oct 2026, D49)

1. `queue_join` is `{mode, entry = 0, stake = 0, clientSeed?}`. The client seed is the one the seat would send in join_room, checked the same way; without one the seat's index stands in, as for join_room. Teams mode is refused with bad_request; an entry and a stake together are refused with bad_request.
2. `queue_status` is `{ref?, state, mode, entry, stake, waited, playersFound, playersNeeded, serverNow, botFillAt?, roomCode?}`. `serverNow` is the server's epoch ms when sent, so the app can show the bot fill countdown with its own clock off. It has no seq; queue messages are outside any room.
3. When a queue holds enough players, the first of them in join order are seated in a new room that starts at once. Each gets queue_status matched with the room code. Their join_room for that code is a rejoin and returns room_state; a matched player who never joins has the usual 60 second reconnect grace, after which a bot takes the seat (free and coin tables) or the seat forfeits (paid).
4. Joining a queue while holding a seat in a room, or while in another queue, is refused with queue_busy. Sending the same queue_join again only repeats queue_status waiting. A second socket for the same user takes over the place in the queue.
5. queue_leave answers queue_status cancelled, or not_found when the socket is not in a queue. A socket that closes leaves its queue. A player who takes a seat by code while queued is dropped from the queue with queue_status cancelled when their group comes up.
6. Until M3.4 and M3.9 only free tables are open: a coin entry is refused with bad_request and a stake with paid_tables_disabled.
7. Queues are kept in memory only. After a server restart the app's reconnect joins the queue again.

### M3.2 bots fill seats (13 Oct 2026, D50)

1. Free and coin queues: players are seated from the front of the queue in groups of a game's size. When the first player of a group has waited BOT_FILL_SECONDS (default 20), that group starts with bots in the empty seats; a group that fills first needs no bots. queue_status waiting carries botFillAt for that moment; paid queues never send it.
2. Bots play at the normal level, the same bot that takes over timed out seats. A bot seat has isBot true in PlayerView, the name "Bot" and its seat number, a user id of `bot:<seat>` that belongs to no account, and is listed in the match's bot seats. Bots have no reconnect grace, so a game left with only bots ends as abandoned.
3. Paid queues: a player who has waited PAID_QUEUE_SECONDS (default 60) is taken out with queue_status timeout, and nobody is charged.

### M3.3 profiles and avatars (13 Oct 2026, D51)

1. User and PlayerView carry `avatar: int`, 0 to 15. An app reading an older server treats a missing avatar as 0. New accounts start with a random preset; bots get their seat number.
2. PATCH /v1/me takes `displayName`, `avatar` or both, and needs at least one. Both are checked before either is saved; a bad value is 400 bad_request.
3. GET /v1/matches/recent returns the caller's last 20 ended matches, newest first: `{"matches": [{"matchId", "mode", "stake", "entry", "abandoned": bool, "endedAt", "rank"?, "players": [{"seat", "displayName", "avatar", "isBot", "rank"?}]}]}`. `rank` is the finishing place, absent for abandoned matches. Other players' user ids are not sent. `entry` is 0 until coin tables arrive (M3.4).
4. A seat keeps the name and avatar it had when the player took it. The match log stores both per player (migration server_002_player_profile), so history shows what the game showed.
5. arena_auth: User gains `avatar`; UserStore gains `setAvatar(id, avatar)` (ArgumentError outside 0 to 15, StateError for an unknown id); migration auth_002_avatar.

### M3.4 coins and daily reward, part 1 (13 Oct 2026, D52)

1. Coins come from the house coin account (`revenue:house:coin`), which may go negative; it is the total of coins in play. Every grant is keyed: `coins:signup:<userId>`, `coins:daily:<userId>:<yyyy-mm-dd Kampala>`, `coins:tutorial:<userId>`.
2. The signup grant is made whenever the server returns the caller's User (login, guest, GET and PATCH /v1/me) and on GET /v1/coins, so accounts made before coins existed get it too. The key makes it once only.
3. User gains `coins: int`, the coin balance.
4. Daily reward: the streak is kept in the claim's ledger metadata. A claim continues the streak if yesterday (Kampala) was claimed, else starts at 1. The amount is capped at day 7, while the streak count keeps going. Two claims at once grant once; the loser gets 409 already_claimed.
5. GET /v1/coins `dailyReward`: `available`; `amount`, which is today's reward when available, else tomorrow's if the streak is kept; `streak`, the days in a row so far, 0 after a missed day; `nextAt`, which is now when available, else the next Kampala midnight.
6. Ledger gains `metadataFor(idempotencyKey)`, null when nothing was posted with that key.
7. Coin tables (entries 50, 200 and 1000, D37) come in part 2 with settlement at game start and game over.
